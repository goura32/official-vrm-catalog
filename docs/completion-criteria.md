# 完成条件・未保存モデルの扱い（2026-10-11）

この文書は、**カタログの完成**と**NASへの人型VRM収集の完了**を分けて判定するための方針。正本は`data/models.json`、`data/collections/*.json`、`data/download-scope.json`。本書の数値はB34継続N/O/P後の履歴スナップショットであり、次回は最新main・実機NAS索引・checkpointを優先する。

## 完成の定義

- **登録・一次調査**：カタログ1,297 IDが一意で、出典・入手方法・利用条件URL・検証段階が記録され、現在の取得可能性を過大に表示しない。非人型もカタログには残す。登録拡充は原則凍結し、確かな誤登録・重大な欠落や実パッケージで判明した別VRMの補正のみ根拠を添えて検討する。
- **人型VRMのNAS保存**：無料で正規取得でき、利用条件が確認でき、実VRMの形状と全身/顔WebPを検査できたIDのみ、ZIP単体（内部`model.vrm`）で保存する。既存IDを上書きしない。保存済み全件の`verify_nas.py`が`ok:true, errors:[]`、索引・ファイルSHA-256が一致すること。
- **未保存の正確な管理**：権利未確定・人型でない・ページ不存在・取得制限・要会員認証・ID対応不明・VRoid Studio書き出し専用などは、根拠と再開条件があれば保留・除外でよい。**1,297件すべてをNAS保存することは完成条件にしない**。一方、無償取得可能な人型VRMを、推測上の「ZIP同梱ファイル」を理由に見落とさない。
- **作業の終了**：現行方針で実行可能な対象が無くなり、残件が理由別に記録されている状態を「現時点の収集フェーズ完了」と呼ぶ。技術的に未検査のものを「実VRM検証済み」に変更しない。保留の解除は**新しい作者根拠・利用条件・正規ログイン・モデル対応資料**がある場合だけ行う。

## 優先する実作業

### 1. 混合ZIPの41 ID（35商品）を再評価

`official_product_page_scope_excluded_not_archived` **38 ID**、`official_package_inspected_scope_excluded_not_archived` **3 ID**が該当。無料ZIPに`.vroid`、Blender、FBX、PSD、Unitypackage等が**同梱されている事実だけ**を「NAS保存不可」の理由にしない。

**実際の既定ルール**は「取得したZIPから許諾・モデル対応が確認できる人型`.vrm`だけを抽出し、単体ZIPへ可逆圧縮してNAS保存。元ZIPや編集ソースは永続保存しない」。配布ZIP全体の一時取得が正規利用・利用規約に沿うなら、混合ファイルでも候補になる。ただし、明白な非人型、年齢・利用条件の懸念、権利矛盾、ID対応不明、取得禁止は**独立した理由として保留**し、単に混合ZIPだから許諾済みとはしない。

最初は公式配布内容とID対応が明確なものから、商品単位で重複取得せず少数検査。例：`tohozunko-zundamon-2025-walking/flying`（1無料ZIP内の歩行/飛行VRM）、`mxu-purin-normal/plus`（同一無料ZIP内の2 VRM）、`neoneko-romuru`・`neoneko-nolt`（作者がVRM個別ファイル名を掲載）。商品ページと実ファイルの条件を新たに照合し、適合したものだけ登録・保存する。独立の年齢・権利判断が必要な対象は保留。

過去の分類・検証履歴は消さず、新たに実取得/形状/権利/保存を確認できたIDだけ`verification`と`notes`を変更する。**41 IDすべてが保存可能、あるいは人型だとは主張しない**。メタデータで「パッケージ実体検査済み」となっていても`notes`に「未取得」とある場合は、実機checkpointで矛盾の有無を確かめる。

### 2. 物理VRMの対応不明14 ID

IDの割り当ては推測しない。実ファイル名、作成者の版・色・衣装表記、VRMハッシュ、既存チェックポイントを照合。1レコードが実際には複数の**異なる独立VRM**を代表していると確定した場合、正本の「1物理モデル/仕様版1 ID」という規則に合わせた訂正案を作り、重複や未確認の増加を避ける。根拠がなければ保留を維持する。

### 3. 利用者操作が必要な対象と停止案件

VRoid Hub16件とENRAI/note1件はBOOTHのログインとは別。正規認証が必要なら個別に利用者操作を依頼し、資格情報は記録しない。VRoid Studio専用23件は無料公式アプリからのエクスポート作業を別タスクとして扱う。埋込権利矛盾130、許諾未確認208は**新しい権利根拠なしに同じ実体を再取得しない**。`dweb.link`の141件（うち要求済み429が9）はホストブロックを保持し、Retry-After経過後も再アクセス・別ゲートウェイによる迂回をしない。
