## 今回の優先実作業：1件で動作証明→同じ依頼で一括拡大

### A. 前提の安全確認

1. Git最新main、ローカル未コミット変更、実NASマウント（`findmnt -T /mnt/hdd/vrm`）、現在のNAS `index.jsonl`、checkpointを照合。`python3 scripts/verify_nas.py --nas-root /mnt/hdd/vrm`を実行して現時点の保存済み件数を確定する。開始時の全index行とSHA-256をローカルに記録。マウント不明ならNASに書き込まず終了。355件がすでに正常保存済みなら一切上書きしない。
2. `booth-real-profile-local-2`の生存とBOOTHログイン状態を**画面で**再確認。ログインが消えていたらユーザー本人の正規ログインが必要と記録し、Cookieコピーや認証回避をしない。BOOTH・各ショップの規約、ページの無料配布条件を確認し、サイトが自動取得を認めない場合は処理を停止して報告する。

### B. Dolly Devilの単体パイロット

1. カタログID `pixellangel-dolly-devil`、商品URL `https://booth.pm/ja/items/4795020`、掲載ライセンスを正本JSONと照合。元記録では個人商用可・法人利用不可・使用時クレジット必須・再配布不可。元ページの最新条件が異なる場合は厳しい方に従い、矛盾が解消しなければ個別保留。NASへの個人用アーカイブと外部再配布を区別し、公開配信やGitHubへのバイナリ追加は行わない。
2. **¥0の`dolly_devil.vrm`のみ**ブラウザーの正規ダウンロード操作で実取得する。`dolly_devil.vroid`、有料品、投げ銭版、購入・決済が必要な操作は対象外。同一商品に複数形式がある場合は正確なファイル名で突合し、取得したVRMのカタログ対応を推測しない。
3. 実ファイルのサイズ・VRM/GLBヘッダー・VRM版・埋込作者/利用条件・SHA-256を`scripts/inspect_vrm.py`等で確認。ファイルがZIPなら安全に内容を列挙して対象VRMを特定。安全でない形式/権利矛盾は保存せず保留。
4. 頭・胴体・両腕・両脚の人型外形を実描画確認できた場合に限り、全身正面Tポーズ`768×1024`と顔正面`512×512`のWebPを生成し目視。プレビュー正面化に失敗したら保留し、他モデル画像で代用しない。
5. 保存可能な場合のみ`scripts/archive_vrm.py --format zip --confirm-humanoid`でNASにモデル単体ZIPと2枚のWebPを登録。`verify_nas.py`で展開後VRM・画像のハッシュ、indexの一意性を検査。ダウンロード原本、配布ZIP、不要画像をNASへ永続保管しない。パイロットの実績・エラー理由をチェックポイントへ記録する。

### C. パイロット成功後に残りの認証待ちを一括処理

1. **Bが取得→人型判定→NAS保存→監査まで成功**したら、別途の承認を待たず、checkpoint上の**BOOTH認証待ち432 ID（旧運用台帳の534件から既処理・再分類を反映）**から既保存、非人型、権利保留、404、アクセス制限、エクスポート専用を除き、公式BOOTHの無料VRM/ZIPを商品ページ単位にまとめて処理する。`VRoid Hub`等、別サービスのログインが必要なIDはBOOTHログインを使えると仮定せず別保留する。
2. 最初は少数（例えば5～10商品）で連続動作・エラー・負荷を確認し、問題がなければ**恣意的な少件数で終了せず**、入手できる分を順次続ける。直列または低並列で配布元へ適切に間隔をあけ、過剰なアクセスをしない。HTTP 429を一度でも返したホストはその時点で**全IDを含め要求禁止**（別ホスト/ゲートウェイ/プロキシへの迂回もしない）。ブラウザーでのログイン・無料ダウンロードを優先し、匿名URLを再調査しない。
3. 1商品に複数VRM・色違い・0.x/1.0同梱がある場合は**既存のカタログIDごとに**内部ファイル名・SHA-256と対応させる。違うモデルや同一モデルを重複登録しない。無料版と有料支援版を区別する。モデル1件ごとに権利/形状/プレビュー/ZIP/索引を検証し、失敗したものだけ記録して残りを続ける。再配布禁止等のライセンスを破らない。
4. 作業機`~/.local/state/official-vrm-catalog/`に`downloaded`, `archived`, `non_humanoid`, `preview_hold`, `license_hold`, `auth_failed`, `free_not_available`, `rate_limited`等の排他的処理状態と再開用ジャーナルを残す。追加取得の進捗件数を適宜ログ出力し、tmux等で中断に耐える。Cookie/認証トークン/期限付きURLはチェックポイントにも出さない。ユーザー本人の追加操作が不可欠になった場合は、その部分だけ保留。
5. パイロットがサイト全体の認証・ダウンロード不具合で失敗した場合は**大量バッチを起動せず**原因を特定し、再取得可能な別の正常な無料商品を最大2件まで限定検証。続けて失敗するなら認証・ブラウザー連携の問題として止めて報告。Dolly Devilが非人型や権利不整合など**その商品固有の理由**で保留なら、他の正規無料候補で1件パイロットを代行してよい。
