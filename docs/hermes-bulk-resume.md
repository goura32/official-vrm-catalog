# Hermes Agent 継続一括実行指示（R3完了後）

対象リポジトリ: `goura32/official-vrm-catalog` / `main`。
**開始基準**: commit `2afaed79f1fe0406d23bc1026e76af17b656bbf8`。このコミットを前提とし、実行直前の最新mainを取得して差分を確認する。差分があればそちらを優先し、既存ユーザー変更は壊さない。

## 目標

**前回のR3実機処理を再実行せず**、未処理の無料VRMを、実行可能な範囲でまとめて確認・取得・描画・保存する。一括で進められる工程をひとつの依頼として実施し、途中で毎工程の承認や重複したレビューを要求しない。最初の対象はPolygonal Mind 100Avatars R1/R2 **200キャラ×通常/Voxel＝400 VRM**（`data/collections/polygonalmind-001-050.json`から`polygonalmind-151-200.json`までの4ファイル）とする。時間と入手先の負荷が許せばHalloween Rising 60件・Xmas Chibis 80件、次に他の作者による直接無料VRMへ順次拡張する。

**最初のR3の成果を保護する**: R3 100件は既に確認済み（人型88、非人型12、NAS保存87、正面画像問題でR3-229を1件保留）。NASにはZIP 87件、全身WebP 87枚、顔WebP 87枚。前回のZIP選択は実測で確定済みで、再ベンチマーク不要。NAS監査結果は `ok:true`・`errors:[]`。登録総数1,297、現行形状候補302/93/902。MJMoonbowの `mjmoonbow-skinnie1-5-41eb4fe` は公開CC0と埋込再配布禁止が矛盾する権利保留。**保留2件のために大量バッチを止めない**。

## 実行の必須ルール

1. 正本は`data/models.json`および`data/collections/*.json`。カタログIDと作者名の対応は正本を使用し、スクリプトに合わせるために正本を改変しない。正確な実測結果での`verification`等の更新は可。明白な非人型は本体取得せず情報だけ保持する。
2. **NASに残す実体は人型VRMの単体ZIP・Tポーズ/顔WebP・index.jsonl・管理ロックだけ**。ZIP内部のVRMファイル名は`model.vrm`。取得元ZIP、画像の中間ファイル、非人型を永続保存しない。画像とVRMは同じカタログIDと元VRM SHA-256で追跡する。外部AI API等にデータを送信しない。
3. 原作者・公式配布で無料取得可能なものだけ。各配布元の利用条件、取得権限、レート制限を尊重する。ログインが必要、権利が不明、購入/NFT保有が必要、アクセス制限がある場合は推測や回避で進めずそのIDを保留し、他を継続する。R1/R2のライセンスをR3のCC0と混同しない。VRM埋込規約と配布元説明の矛盾は個別保留。
4. ZIPとzstdの比較、NAS保存87件、R3の形状確認、すでに成功した4ユニットテストは**同じ条件のまま再調査・再実行しない**。環境変化や実際のエラーがあれば該当箇所だけ確認する。新しい検査用のコードや追加レビューを無制限に増やさず、実際の取得・保存を進める。
5. 人型判定に全件の事前画像分類を要求しない。不明なものは無料取得条件を満たせば一時取得し、VRM実体を解析・ローカル表示して判定する。Humanoidリグがあることだけを人型の根拠にしない。標準版とVoxel版を同じ外見だと推測しない。真正面のTポーズと顔のWebPができたものだけNASに確定保存する。
6. `/mnt/hdd/vrm`が正しくNASマウント（前回`nas1.local:/volume1/hdd`のNFSv3と記録）に存在することを`findmnt -T /mnt/hdd/vrm`と実体確認で判定する。マウントがなければ**ローカル同名パスを作って誤保存しない**。既存のZIP/WebP/indexを削除・上書きしない。`archive_vrm.py`のindexロックはNFS環境向け書き込み専用オープンに修正済み。
7. 作業機の`~/.local/state/official-vrm-catalog/`などにID別の処理チェックポイントを記録して再開可能にする。各IDの状態は取得前除外、権利保留、取得成功、VRM不正、人型/非人型、描画失敗、保存済みを区別する。ログはNASに置かず、GitHubにはVRM/ZIP/WebPや認証情報をpushしない。

## 一括手順

1. **再開点の確定**：最新main、`docs/hermes-bulk-run-results.md`と`docs/nas-storage.md`、NAS `index.jsonl`、前回checkpointを確認。NAS全件検証`python3 scripts/verify_nas.py --nas-root /mnt/hdd/vrm`を一度実施。**既に正常保存済みの87 IDをすべてスキップ**する。R3-229は品質保留として別扱い、MJMoonbow権利保留も再取得しない。
2. **R1/R2優先**：400件の正本IDとGitHub配布元、利用条件を照合してキュー化。制作者のREADMEで正規の無料取得条件を確認。標準・Voxelごとに、作者プレビューから明確な非人型だけ取得前除外。それ以外はVRMを一時取得、GLB/VRM版・作者と権利メタデータ・SHA-256を確認し、実物レンダリングで外形判定する。非人型は保存しない。
3. **画像と保存**：実機で人型と確認したVRMからTポーズ全身`768×1024`と顔`512×512`のWebPを生成し目視品質判定。正面・欠損・切れ・異なるモデル画像混入をチェック。プレビュー・VRM SHA-256を照合後、`scripts/archive_vrm.py --format zip --confirm-humanoid`でNASへ保存。既存ZIPと同一SHA-256ならハードリンクを利用。NASのNFS遅延・一時タイムアウト時は**対象IDのZIP・画像・索引を再照合し、整合確定までは成功としない**。無条件再試行・上書き・削除をしない。
4. **後続シリーズ**：R1/R2キューの処理可能分が終了したら、同一の依頼でHalloween 60 / Xmas 80へ継続。こちらはIPFS公開URLと作者管理のCC0索引が取得根拠。ゲートウェイが応答しないときは低頻度の限定リトライとチェックポイント記録にとどめる。さらに余力があればMJMoonbowの権利保留以外、NeonGlitch86のライセンス確認済み、他の作者の直リンクと進める。BOOTH等のログイン必要分は適切に保留し、全体は止めない。
5. **最終監査とpush**：実行範囲が一区切りついたら`python3 scripts/verify_nas.py --nas-root /mnt/hdd/vrm`を再実行して完全一致を確認。正本の確認済み部分と選別ID、集計レポートを事実に合わせ更新し、変更パスを限定してcommit/push。連続作業が長い場合はtmuxで中断耐性を確保し、チェックポイントを維持する。R3実績・保存済みハッシュを変更しない。既存未コミット変更があれば安全に対象を切り分ける。
