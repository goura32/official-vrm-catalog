## 依頼する作業

`goura32/official-vrm-catalog`の**1,297件の無料VRMカタログ**について、利用規約に従って入手できるものを実機検査し、人型モデルのVRMだけを`/mnt/hdd/vrm`にロスレス圧縮して永続保存してください。人型か事前不明でも一時取得・3D表示で判断して構いません。**元の配布ZIPは永続保存しない**。人型モデルから`768×1024`の正面全身Tポーズと`512×512`の顔正面画像をWebPで生成し、VRMの`catalog_id`・未圧縮VRMのSHA-256と結び付けて保存してください。

**この依頼は調査→小規模の実機検証→必要な最小修正→連続バッチ実行→照合→commit/push→最終報告まで一括**です。各小工程で確認を求めたり、同じレビューを何巡も繰り返したりしないでください。長時間作業は`tmux`等でセッションを維持し、進捗・障害を記録して再開できるようにしてください。チャットへの報告はまとめて最後に行ってください。ただし、認証・権利・NASマウントの安全性・有料取得など利用者本人の判断が不可欠な作業は勝手に進めず、その対象だけ保留します。

## 最優先で守る条件

1. 既存カタログJSONが**正本**。`data/models.json`と`data/collections/*.json`のID、モデル名、出典を維持する。スクリプトに合わせて正本を書き換えない。確実な誤記以外の新規登録を追わない。登録規模は現時点で1,297件。
2. 人型に該当するのは人物に近い**頭・胴体・両腕・両脚**があるモデル。亜人・人型ロボット・二足獣人・人型モンスターは候補。VRMのHumanoidリグがあるという理由だけで人型とは判定しない。判定できないものは保留し、NASに保存しない。
3. `data/download-scope.json`の既知非人型81件は取得不要。214件の人型候補も外形確定・取得成功を意味しない。未判定1,002件は**ダウンロード前に画像判定を全件完了させる必要なし**。実物検査の中で確認する。分類結果の更新は根拠があるIDだけ。
4. **公式・作者が無料公開し、合法・正規に取得できるものだけ**。第三者転載、有料購入、NFT所有必須、CAPTCHA突破、年齢制限やアクセス制限の回避は禁止。通常の無料ログイン・会員登録・年齢確認が必要な候補は「認証待ち」として記録し、パスワード等を要求・記録しない。ライセンスが不明で正当な取得根拠のない候補は保留。原本/画像は外部のAI APIにアップロードしない。
5. **NASに保存するのは人型VRMの圧縮ファイル、Tポーズ・顔WebP、`index.jsonl`、必要なロックだけ**。非人型、配布ZIP、余剰サムネイル、作業用ログ・一時ファイルはNASへ永続保存しない。作業ログと進捗は実行機の`~/.local/state/official-vrm-catalog/`等に保持。元ファイルは一時作業場から成功後に消去。GitHubにVRM/ZIP/WebP実体、認証情報、個人情報、NASの一時ログをpushしない。
6. **NASパスの実体を最初に検証**。`/mnt/hdd/vrm`を単純なローカル作業フォルダとして新規作成しない。`findmnt`等でホスト・実マウント・ファイルシステム・空き容量と書込権限を確認し、ユーザー指定のNAS領域だと確信できないなら保存処理を停止する。必要な既存SSH接続が使える場合のみ正規の方法でNAS側を操作する。
7. リポジトリに既存の未コミット変更があれば壊さない。作業内容だけを限定的にstageし、日本語の簡潔な結果とともにcommit/push。GitHub ActionsもRDCも使わない。システムの危険な一括削除はしない。NASデータを上書き削除しない。

## 一括実行の順序

### A. 環境を確認して最小検証

- README、`docs/nas-storage.md`、`docs/collection-policy.md`、`docs/download-scope-review.md`を読み、`scripts/inspect_vrm.py`、`scripts/benchmark_vrm_compression.py`、`scripts/archive_vrm.py`、`scripts/verify_nas.py`、`tools/vrm-preview/`の最新仕様を確認する。
- `python3 scripts/validate.py`、`python3 -m unittest discover -s tests -v`を**一度実行**。失敗したらまずテスト用合成WebP・コードのどちらに問題があるか根拠を確認し、必要最低限の修正と該当テスト再実行だけを行う。新たなテストを大量追加しない。
- node/npm、Chromium、zstd、WebGL、NASマウントと十分な空き容量を確認。VRMをダウンロードする前に、出典・ライセンス・ファイルサイズの安全基準を設ける。大きすぎるファイル、ZIP爆弾、不正な内部パスは保留して記録する。

### B. 実VRMで圧縮・プレビューの試行

- 異なる作者・ファイルサイズ・VRM 0.x/1.0から**3〜8個の正規取得可能なVRM**を選ぶ。機能テスト用や明らかな非人型は「画像生成できる人型のサンプル」として扱わない。モデルの来歴と形式を索引に対応付ける。BOOTH等で権限が不明ならGitHubの公式・作者直リンクから始める。
- 同じ3件以上を`scripts/benchmark_vrm_compression.py`に渡し、ZIP Deflateとzstdの**元サイズ・圧縮サイズ・時間・元VRMと復元後のSHA-256一致**を記録。`docs/nas-storage.md`既定の**差3%以内ならZIP、それ以上ならzstd**を全保存分共通の形式として確定。zstdが無い、サンプルが少ない場合は決め打ちせず必要な環境を整えるか保留とする。
- `tools/vrm-preview/generate.mjs`で全身Tポーズ・顔WebPを生成。**実際の画像を目視**し、人物の正面・Tポーズ両腕両脚・顔の大きさ・黒/空画像・切れ・左右方向を検証。必要なカメラ調整のみ修正。画像生成ができない個体は原因を記録し、他モデルの画像で代用しない。
- 人型と実物確認できたモデルを`scripts/archive_vrm.py`で保存。**圧縮復元したVRMと元VRMのSHA-256一致、プレビュー画像と元VRMのSHA-256対応、index.jsonlの内容**を検査する。`--confirm-humanoid`は検証根拠があるモデルだけに指定。

### C. 同一の依頼の中で取得可能分を連続バッチ処理

- PoCが通過したら**追加指示を待たず**、まず公式/作者直接VRM URL、次いで無料ZIP/公式配布ページなどの取得可能な範囲をキュー化。既知の非人型、既存NAS索引に正常保存済みのID、明白な有料物や権利不明物はスキップする。モデル規模1,297件の**処理可能な候補をできるだけ全件**走査し、任意の20件などで打ち切らない。
- 再実行可能な**チェックポイント/ジャーナル**を作る。IDごとに`saved`,`excluded_non_humanoid`,`unresolved_shape`,`auth_required`,`license_blocked`,`download_failed`,`render_failed`,`invalid_vrm`などの状態、理由、試行時刻、URL、ハッシュを記録。**失敗1件で全体停止させず**次へ。復旧できる一時エラーだけ回数上限を設け、エラーを無限再試行しない。
- 同一ZIPに複数VRMがあればZIP内パスとIDの対応を照合し、人型だけ抽出・圧縮・撮影・永続保存。同一VRM SHA-256の別IDは保存スクリプトのハードリンク再利用で重複容量を抑える。**外見不明・プレビュー不良のものを自動的に人型確認済みにしない**。連番や作者名だけの一括判定は禁止。目視可能なコンタクトシート等で効率化してよい。
- ZIP・VRMのダウンロードは適切に速度と並列数を制限し、配布サーバーに負担をかけない。無料アカウントに多数の自動アクセスを試みず、ログインが要るものは保留リストに積む。すべての作業は途中中断・再開可能にする。

### D. 保存結果の照合・レポート・反映

- 最後に`python3 scripts/verify_nas.py --nas-root /mnt/hdd/vrm`を実行し、保存済み全件について、圧縮ファイル・復元SHA-256・画像の実寸法とSHA-256・索引IDの一意性を確認。不整合は**対象IDだけ**安全に修復。検証前に成功として集計しない。
- GitHubにプログラム/文書/検証済みの分類ID（根拠が明確なもののみ）と集計結果を反映。実ファイルや個人認証情報はpushしない。ユーザーの既存差分を巻き込まない。
- 最終報告は短く、**実際の数値**で「対象候補、取得試行、取得成功、人型確認、NAS保存済み、非人型除外、判定保留、認証待ち、失敗、圧縮前後合計サイズと削減率、プレビュー作成成功、NAS再監査結果、Git commit SHA、継続時の再開方法」を示す。未実施・未確認を成功と書かない。
- 全体の未消化が残る場合も、**チェックポイントと安全な再開コマンド**を残し、次回こちらが長文の繰り返し依頼をしなくてよい状態にする。認証が必要な配布物や権利の保留は別一覧にする。
